[单页汇报 PPT](第七周汇报_仿真内容介绍_单页.pptx) 沿用第六周白底紫色风格，附 HTML 超链接及详细演讲者备注。PPT 与 `全厂制造仿真.html` 保持同目录。`presentation/` 保留作者脚本，其中包含本机 Codex 创作工具路径；重新制作 PPT 需要对应工具环境并调整路径，直接使用成稿不受影响。

## 操作

- 开始/暂停、推进一分钟、重置、倍速、拖动时间轴、跳至结束。默认从第 10 分钟开始播放，便于直接观察运行状态；重置回到第 0 分钟。
- 滚轮缩放、拖动平移、双击放大；可回到全厂、A2/A3、所选对象或全屏地图。小地图可点击定位。
- 车辆：点击查看当前物料、接货与送货设备、空驶/载货路径、任务进度、距离和最近搬运记录，可跟随行驶。
- 设备：点击查看当前加工、加工进度、实际队列、待到达来料、累计利用率。
- 物料：从车辆或设备详情进入，也可在左侧搜索。查看当前状态、累计等待、所在端口及后续工序；可跟随物料跨设备流转。
- 左侧按区域、车辆、设备、物料浏览，支持搜索、仅显示运行中对象和逐批加载；所有 500 辆车均可查到。
- 显示/隐藏空闲车、设备名称、所有车辆当前行驶路径。默认只突出所选任务路线，其他车辆始终执行各自任务。
- 底部运行事件可只看所选对象；可导出当前时刻统计。

### 产品、工艺与镜头

顶部可按产品线（part_1–part_10）、工艺大类、精确设备组和具体步骤交叉筛选；勾选“仅看相关对象”可单独观察。产品视图依据截至当前时刻真实请求的搬运和设备分配，不将全部潜在兼容设备误当产品专线。筛选只改变观察范围，其他产品仍在模型中竞争共享设备与车辆；上方实时指标始终统计全厂，地图上方和右侧另列筛选范围统计。

选择产品后会出现按原始顺序排列的工艺条，支持翻页、点击步骤；相同工艺反复出现表示回流，不是固定物理流水线。工艺视图保留该类全部设备，外部接货来源用灰色端点保留。设备详情始终展示完整共享队列。

选定产品后，默认用粗紫线突出截至当前时刻已派车任务的载货规划路线，重合线段合并显示；可通过“显示产品路线”单独隐藏或恢复。路线服从当前工艺、设备组及步骤筛选，拖回较早时刻时不会保留之后才分配的路径。该图层不包含空驶，也不凭空连接未来工序；隐藏它不影响车辆、设备或所选单次任务的路线。

“设备配色”可切换运行状态和设备种类。种类配色沿用前期布局图的 11 个生产类别，另列固定物流设施；同类设备填色保持一致，加工与排队由绿边、橙边及进度条表示。精确组名仍决定兼容性，不能因为种类同色就任意替换。

“镜头”可选自由浏览、所选路径全景、跟随所选、设备特写。路径全景容纳当前任务的空驶和载货路线；跟随适用于车辆或物料；手动平移、缩放会退出自动镜头。镜头切换不改变仿真时刻或结果。

页面提供“全厂运行 / 产品工艺 / 干刻资源 / 回流批次 / 排队特写”五个演示入口。具体演示顺序和可直接口述的例子见 [汇报演示建议](汇报演示建议.md)。

## 数据和运行范围

| 内容 | 采用的数据 |
| --- | --- |
| 空间 | SMAT2022 全厂有向轨道、端口、43 个 Bay |
| 加工资源 | 1,068 台生产设备，另有 48 个固定物流设施 |
| 车辆 | 原表全部 500 辆 OHT，保留各自初始轨道位置 |
| 工艺 | SMT2020 LVHM 的 10 类产品、4,013 道路线记录，含 Delay |
| 初始物料 | WIP 表全部 2,156 条记录的 PART、CURSTEP |
| 新物料 | 常规订单间隔按 0.25 倍速率折算，12 小时内新增 10 批；不生成 HotLot/SuperHotLot |
| 时段 | 12 小时，连续工艺推进，运行窗口结束时保留未完工和在途状态 |

WIP 表未记录具体设备和剩余加工时间。因此将初始物料放在上一道生产工序的某台可加工设备端口，并从 CURSTEP 开始请求运输。这会形成初始集中搬运波峰，属于明确重建的初始情景，不能解读为真实现场瞬时状态。

## 事件模型

物料沿剩余工艺路线前进：请求搬运 → 等车/空驶接货 → 装载 → 载货运输 → 卸载 → 排队 → 加工 → 下一道工序；最终运输到 COMPLETE。Delay 工序单独计时，不占用机器。

搬运请求全局 FCFS，选择沿有向轨道接货距离最短的空闲车；单车同时只执行一次搬运。设备按“未完成工作量＋预计运输时间”选取，实际到达后 FCFS 加工；单机一次一批，车辆在加工期间释放。输入输出缓存无限，加工完成不因出站等车阻塞机器。

所有路径由同一个有向最短路模块生成，动画沿同一组轨道节点和端点插值。图上的空驶虚线、载货实线与车辆位置共用同一条路径，未另造演示路线。

参数与简化：

- 假设原始坐标单位毫米，恒速 1500 mm/s；装载、卸载各 15 秒。距离按轨道端点曼哈顿长度计时，弯轨用端点折线近似。单位未现场校准，显示的是换算假设下的仿真时间。
- 每片加工按 25 片/lot 换算。批加工按代表批量折算为等效单 lot 机时，再除以 0.85；没有显式组批。
- 未建模车辆安全间距、轨道互斥、ZCU、加减速、故障维护、返工和抽检。因此车辆可能同段行驶，等车/等设备不能当作真实交通拥堵。
- 当前是**全厂参考布局的运行基准**，未重新求解全厂 MILP，也未将该全厂结果当作优化前后收益。
- Bay 外框由设备及所属轨道包络推导，是区域示意。

## 当前运行结果

在上述情景的 12 小时内，500 辆车全部参与调度，40 个生产 Bay 都有生产任务，1,061 台设备开始过加工；产生 11,415 次搬运请求，完成交付 11,373 次、完成加工工序 9,333 次，11 批物料走完剩余工艺并运抵 COMPLETE。其余物料在窗口结束时仍可能等待、运输或加工。

界面统计随当前时刻重算。运输平均用时只统计已经交付的请求，从请求发出算到卸载完成；累计距离包含当前正在行驶路段的已走部分。时间轴和倍速不会改变已生成的事件结果。

## 复现与验证

从仓库根目录执行，使用 Python 标准库：

```powershell
python week7/factory/model.py
python week7/factory/build.py
python -m unittest discover -s week7/tests -v
```

模型输出位于 [factory/factory-data.json](factory/factory-data.json)，包含搬运、加工、等待、路径和资源事件。修改参数后重新运行模型和打包脚本。HTML 内嵌全部数据和资源，不需要服务或网络。

可选前端检查：

```powershell
cd week7
npm install --ignore-scripts --no-audit --no-fund
npm run test:ui
```

验证覆盖可手算的排队案例、路径方向与长度、车辆位置连续/互斥、加工互斥/FCFS、设备兼容性、工艺先后约束、各时刻资源守恒及对象选择、搜索、播放和路径一致性。前端使用 DOM 执行检查与独立 SVG 渲染，不作为真实浏览器布局验收。

旧局部模型源码及结果保留用于追溯；其构建脚本只生成历史页面，不覆盖新的全厂入口。
